# Ember audit 002, 13 September 2026

Mode: after (audit of the finished app). Method: served `index.html` with `python3 -m http.server 8765`, used it in the app's browser pane at 1100 px, 375 px, and 280 px, in both themes, from a cleared browser: first run, adding, finishing, unfinishing, removing, Add for tomorrow, Fuel, History, Settings, import, theme switch, keyboard walk, then with a seeded two-year history (731 days, 5,511 tasks) and fifty tasks for today, then the clock moved past midnight. Contrast ratios computed with the antislop checker. Nothing in the repo was changed.

What the harness could not do, so is judged from the code and stated as such: send a native Enter or Space to a button (activation was proxied with `.click()`, so focus behaviour was verified, key handling was not), observe the service worker's cache (the pane hides it from the page), open the native date picker, install on iOS, emulate reduced motion.

Priority: MUST = breaks use, hides content, or fails a hard gate. SHOULD = falls short of the four standards (hyper-minimal, luxurious, lightweight, useful). COULD = polish.

## MUST

### 1. On phones the bottom bar covers the last row

- Where: `index.html:549` (`main { padding: 1rem 0.9rem 4rem }` under 400 px) and `index.html:553` (3rem under 290 px) override `index.html:225`, which set the bottom padding to `6rem + env(safe-area-inset-bottom)`.
- What: at 375 px the padding is 60 px and the bar is 65 px, so the last row already sits under the bar's top edge. On an iPhone with a home indicator the bar is about 99 px, so the bottom 39 px of content is unreachable: the Erase everything link in Settings, the last task on a long Today, the Show older days link in History.
- Standard: R-03 (mobile layout must be perfect), C-4.
- Fix: in the two narrow rules set `padding-bottom: calc(6rem + env(safe-area-inset-bottom))` instead of a bare length, or drop the bottom value from the shorthand so the 700 px rule keeps it.

### 2. A screen reader hears the streak without its number

- Where: `index.html:601`. The numeral is `aria-hidden`, the status span gets an `aria-label` at `index.html:897`.
- What: `role="status"` is a live region; what it announces on change is its text content, which is "-day streak. Finish today to keep it." The aria-label is read only when the element is navigated to directly, and many readers ignore aria-label on a plain span. The one number the app exists for is the part that goes missing. Confirmed: the status's `textContent` is "-day streak. Finish today to keep it." while its label is "122-day streak. ...".
- Standard: R-32, C-4.
- Fix: put the numeral inside the status span (or make the whole `.streak-line` the status), drop `aria-hidden` on the count and the `aria-label`. Visual layout stays the same.

### 3. Every view opens at the previous view's scroll offset

- Where: `showView` at `index.html:917` never resets scroll.
- What: with fifty tasks, scroll to the bottom of Today, tap History: it opens on rows from mid August, no hearth, no grid. Tap Settings from there and it opens on the data links. On a phone this happens daily. Screenshot at 375 px reproduced it.
- Standard: useful; a person would think the grid had vanished.
- Fix: `scrollTo(0, 0)` at the top of `showView`, and in `renderHistory` when opening or leaving a day page.

## SHOULD

### 4. Finish your first day, add one more thing, and the app says you have no streak

- Where: `streak()` at `index.html:824`: when today is not done it counts from yesterday, so on day one it returns 0.
- What: reproduced. "You are fire. 1-day streak. Today is done." then add a Fuel item: "Light it up. No streak yet. Finish today's list to start one." The flame goes from lit to out, not to warm. On any later day the same act reads "N-day streak. Finish today to keep it", which is what README promises ("makes the flame warm again"). Day one is the day that decides whether a person comes back.
- Standard: useful; the two states contradict each other and the README.
- Fix: record the day the flame last lit (`state.lit = today()` when the day tips into done, in `toggleTask`) and in `streak()` use `Math.max(n, 1)` while `state.lit === today()`. Two lines.

### 5. The offline copy of the page is never refreshed

- Where: `sw.js:19` and `sw.js:21`: `caches.open(CACHE).then(c => c.put(..., res.clone()))`.
- What: `caches.open` is asynchronous; by the time its callback runs the browser has started consuming the response body, and `clone()` on a used body throws. The put never lands. Online you always get the fresh page (network first), but offline you get the copy from the last service worker install, and a change to `index.html` alone never triggers a reinstall. The comment at the top of `sw.js` promises the opposite. Not measured here: the pane hides the worker's cache from the page (it stayed empty even in a fresh tab), so this is from the code and the documented behaviour of `Response.clone`.
- Standard: useful; the install promise in README ("works offline") drifts from what a person gets after the first update.
- Fix: clone synchronously: `const copy = res.clone(); caches.open(CACHE).then(c => c.put('./index.html', copy)); return res;`. Same for the other branch. Verify in Chrome DevTools, Application, Cache Storage.

### 6. Choosing Dim or Bright does not move the browser chrome

- Where: `index.html:17` and `:18` tie `theme-color` to the OS setting; `applyTheme` at `index.html:846` sets `data-theme` and nothing else.
- What: pick Dim on a light OS and the page is dark while the address bar, the PWA title bar, and the Android task switcher stay paper. Confirmed: with `data-theme="dark"` both meta tags still read as written.
- Standard: luxury (a considered object does not have a mismatched frame); R-34.
- Fix: in `applyTheme`, set one `theme-color` meta's `content` to the computed paper colour and drop the two media-scoped tags.

### 7. The filled ink segment is the heaviest mark on the page

- Where: `index.html:200`, `nav button[aria-current="page"] { background: var(--ink) }`.
- What: on wide screens the active view is a solid black block 40 px tall. It outweighs the flame, which DESIGN names as the one focal point on every screen, and it is the only filled rectangle among hairlines. The phone bar solves the same problem with an ember icon and ink text, and reads as the same app only by the labels.
- Standard: luxury (marks heavier than they need to be), Part 3 one focal point. DESIGN's reason, "no ambiguity in either theme", is met by ink text on muted text (16:1 vs 5:1) without the fill.
- Fix: active segment in ink text with a 1 px ink rule under it, or the phone treatment (ember icon, ink label) at all widths. Then the desktop icons (see 13) become the state carrier and earn their place.

### 8. The History grid is 35 tab stops, and the rows repeat it

- Where: cells are buttons at `index.html:1115`; rows at `index.html:1132` cover the same days.
- What: keyboard users press Tab 35 times to reach the first row, then 30 more for the rows, and the rows say what the dots say. The response to audit 001 kept the rows "because the dots carry no text"; the dots have aria-labels, so they do.
- Standard: R-32 (logical, not exhausting, tab order), hyper-minimal (one path per result).
- Fix: keep the grid as the tab-able element (one stop, arrow keys move between cells: about ten lines), and start the rows where the grid ends (filter keys older than 34 days). If the rows must stay, make the grid `tabindex="-1"` and non-interactive.

### 9. Fuel is explained three times on one empty screen

- Where: lead at `index.html:644`, placeholder at `index.html:646`, empty note at `index.html:1064`.
- What: "Whatever you add here is on every new day's list." then "Something you do every day" then "No fuel yet. Add the things you do every day, like a walk or ten pages." Three sentences, one meaning, before the person has typed anything. History has the same shape on day one: "0 of the last 1 listed day fully done." above "Nothing here yet."
- Standard: hyper-minimal, copy no longer than needed; R-27 asks for an empty state that names the next action, one is enough.
- Fix: keep the placeholder, delete the lead and the empty note. In History, show the lead only when at least seven days are listed, or drop it: the grid is the sentence.

### 10. Done is said three times, and two rungs of the ladder are the same rung

- Where: slogan at `index.html:899`, streak line at `index.html:892` ("Today is done."), date hint at `index.html:1033` ("All done."). Ladder: `'You are fire.'` for 1 to 2 days, `'You are on fire.'` for 7 to 29.
- What: "You are fire. 1-day streak. Today is done. Sunday, 13 September. All done." Four lines of hearth and date say one fact. And "You are fire" against "You are on fire" cannot be told apart, so the thirty-day ladder has a missing step at its most-seen rung.
- Standard: hyper-minimal; copy.
- Fix: drop "Today is done." from the streak line (the lit flame says it) and keep "All done." beside the date, or the reverse. Replace one of the two "fire" lines with a distinct one, or collapse to four rungs.

### 11. The "waiting for tomorrow" line and Add for tomorrow both sit inside the day's frame

- Where: `index.html:637` to `:638`.
- What: with one task queued, Today shows an underlined sentence between the input and the list, in the same link style as Dim, Show older days, and the data actions, so the eye reads it as a control before reading it as a fact. Opened, it becomes a second list with its own remove crosses above the real list. It is a good fix for audit 001 finding 13, but it is the only element on the screen that is not the box, a task, or the streak.
- Standard: hyper-minimal ("one box to type in, one tap to finish, the streak").
- Fix: fold it into the date line's hint ("3 left. 1 for tomorrow.") and let the calendar button or the tomorrow link open the list. Same information, one fewer row.

## COULD

### 12. Every finished row shows its cross

- Where: `index.html:374`, `li.done .remove { opacity: 1 }`.
- What: on desktop the cross is hidden until hover on open rows but always shown on done rows, so a finished list of fifty is fifty crosses down the right edge. DESIGN gives the cross one job, removal, and a done task is the one you least need to remove.
- Fix: delete `li.done .remove` from that selector; hover and focus still reveal it.

### 13. Desktop nav carries icons and labels

- Where: `index.html:606` to `:623`, `nav svg` at `index.html:198`.
- What: on wide screens each segment is an icon plus a word; the word alone is unambiguous, and DESIGN's reason for the icons is the phone bar. Four glyphs that repeat four words.
- Fix: `nav svg { display: none }` above 700 px, unless finding 7 makes them the state carrier.

### 14. The page shifts 7 px when the scrollbar appears

- Where: `main { margin: 0 auto }` at `index.html:80`.
- What: on Windows and Linux, adding the fourth or fifth task makes the column jump left as the scrollbar arrives; confirmed in the pane (content moved from x 217 to x 211).
- Fix: `html { scrollbar-gutter: stable }`.

### 15. A toggle rebuilds and re-measures the whole list

- Where: `renderList` at `index.html:988` clears the list, rebuilds every row, and reads `getBoundingClientRect` on each before and after.
- What: 20 ms for 52 rows on a desktop, so likely 60 to 100 ms on a mid phone, at the exact moment the glide starts. All other measurements are comfortable.
- Fix: measure only rows whose index changed (the toggled row and those between its old and new slot), or skip FLIP when the list is longer than about 30 rows.

### 16. First-run dialog names Fuel before Fuel exists, over a note that is already showing

- Where: `index.html:705`; `render()` at `index.html:1534` runs before `askConsent()` at `:1535`.
- What: the dialog says "tasks, Fuel, streak, and theme" to someone who has not seen the Fuel tab. Behind the blur, "Not saving to this device. This list lasts until you close the tab" is already on the page before the person has answered.
- Fix: "tasks, streak, and theme" (Fuel is a task). Call `askConsent()` before the first `render()`, or render after the dialog closes only.

### 17. Settings facts read oddly

- Where: `index.html:1221` and `:1224`.
- What: "On, since Today" (since today is fine; since Today capitalised reads as a name). "Days recorded: 2" on the first day, because the list made for tomorrow counts; History at the same moment says "Nothing here yet."
- Fix: lowercase the label from `dayLabel` here, and count only keys `<= today()`.

### 18. The day page says its total twice

- Where: `index.html:1161` and `:1166`.
- What: "All 6 done." then "DONE (6)". When some are undone: "4 of 6 done." then "DONE (4)" and "NOT DONE (2)".
- Fix: drop the counts from the group headings.

### 19. A task for a far day lives forever

- Where: cutoff at `index.html:803` drops only past days; the picker at `index.html:1453` has a `min` and no `max`.
- What: choose 2031 by mistake and "One task waiting for later days" sits under the input for five years with no other way to find out which day. The list does show the day when opened, so it is findable, just permanent.
- Fix: `picker.max` a year out.

### 20. The input's underline is twice the weight of every other rule

- Where: `index.html:235`, `border-bottom: 2px solid var(--line)`, and the 2 px ember draw-in.
- What: rows, nav, facts, and dialogs use 1 px hairlines; the box uses 2 px in the rest state, and on a lit day the ember draw-in is the second-heaviest orange on the screen after the flame.
- Fix: 1 px rest line; keep the ember at 2 px only while focused if the draw-in needs it, otherwise 1 px too.

### 21. Docs

- README "Keyboard": "the next stop is its remove button" is true; add that Escape closes any dialog. DESIGN "Sizes" says nav wraps on watches; it hides labels instead (`index.html:559`). DESIGN "Motion budget" lists the slogan fade (`.slogan.swap`) nowhere.

## Decisions in DESIGN.md worth a second look

These were raised in audit 001 and declined; recorded once more without re-arguing, because the brief for this audit asks that decisions be questioned and that removals be preferred.

- The calendar button (`index.html:630`). It is the one control in the input row that is not the box or one tap, and it exists for a case the person meets rarely. Tomorrow plus Cmd+Enter covers the common case. If it stays, it stays; it is now well built.
- The first-run consent dialog. The data never leaves the device, so the dialog asks permission for something the person came to do. Saving by default with Stop saving in Settings would make the first ten seconds the app's best ten seconds.
- The header Dim/Bright link. Settings holds the same choice. A lone underlined word at the top right is the one place the page reads as a website rather than an object.
